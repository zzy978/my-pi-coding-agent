# SWE 单候选 A＋B 晋升审核

## 目标与授权

用户已批准接通 SWE 实验证据链、模拟验证、单候选 12 次真实运行和资格审核。候选固定为 `2d5f07e8-9432-4a07-adb0-5e9a84ae312f`，A 为来源任务 `django__django-12713`；B 在运行前从另一道适用 Django 题中固定。每题三对新鲜运行，仅候选组注入该候选。不得执行晋升、改写历史产物或调用 critic。

## 现有逻辑与边界

SWE 使用 runSweTask、独立 Docker 环境和官方评分；普通 experiment 使用受管 Git worktree。SWE manifest 的 replayable=false 是真实状态，不能伪造为 true。原有 promotions 按本地 Git 根目录归组；容器仓库身份须使用已冻结数据集 repo 字段及任务哈希单独校验，不能误把宿主占位目录当作 Django 仓库。

## 最小实现

新增 SWE 单候选实验入口和可重算审核，复用容器执行及评分，不修改普通 worktree 隔离校验。独立新批次保存冻结候选、来源引用、A/B 任务、镜像与评分器指纹、运行源码及依赖快照、每对两臂、运行和补丁哈希。运行开始前保存当前槽位，重启不盲目重跑未知付费请求。逐臂校验协议，停止设施错误；评分失败是结果，不能为得到通过而重试。

资格审核要求同 repo 两个不同问题，其中一个非来源问题；每题至少三对、完整有效、无退化、至少一项改善、无受保护路径或验证器破坏、无冻结漂移。读取实际 run、benchmark、trial、score 和 patch 重新计算，不相信保存的汇总布尔值。输出证据门槛审核与尚未执行的人工晋升状态，不把 SWE 审核文件冒充旧 worktree experiment 文件或有效晋升事件。

## 验证

模拟覆盖全部通过且有改善、零改善、退化抵消总收益、不完整、重复运行、错误候选、同题改 ID、跨 repo、图片/配置/哈希漂移、恢复未知结果及基础设施错误。真实运行前做两题红基线/金补丁评分预检。执行 check、完整 test、lint、build。最终审阅 12 份 diff 和评分日志，报告实际调用数、已记录用量、费用及资格限制。
