# Mini 经验库的新任务泛化实验

从 SWE-bench Verified 固定版本 `c104f840cc67f8b6eec6f759ebc8b2693d585d4a` 抽取40题，排除 Mini 的任务ID和规范化后重复的问题文本。随机排序使用种子 `mini-transfer-v1` 与任务ID的SHA256；不按模型结果或参考补丁难度挑选。

| 分组 | 仓库 | 题数 |
| --- | --- | ---: |
| 原仓库新问题 | Django、Sphinx | 各10 |
| 新仓库问题 | pytest、Requests、scikit-learn、SymPy | 各5 |

每题执行无经验组和经验库组各一次，共80次模型任务。各题两臂相邻，20题无经验先运行、20题经验先运行；两臂均为新容器、新会话，固定同一模型、high、工具、预算和独立官方评分。

## 经验使用方式

只使用 Mini R0 复盘后冻结的39条首候选，核验经验包、源运行及候选哈希。不根据 Mini B 结果挑选或修改经验，也不使用本次任务结果更新经验。经验为文本指导，不安装Skill，不改变权限、模型或评分规则。

新批次默认使用 V2：先为冻结候选生成独立检索描述，再仅用公开问题做中英文 BM25 Top8 召回。文本模型依据原经验检查触发条件、排除条件、适用阶段和冗余；仅直接适用、排除条件不存在且适合初始阶段的经验可以注入，最多2条、9000字符，允许零注入。候选正文不改写或裁断。首次准备即冻结全部选择，后续执行与恢复不重新判断；无经验臂始终不注入。

已有 V1 批次继续使用原算法：公开仓库名和问题描述 BM25、至少两个词命中、最多3条。不得把 V2 选择写回旧批次；源码或协议漂移仍拒绝续跑，需要原匹配版本。

任务容器不挂载宿主目录、不联网，不包含经验库全集、参考补丁、隐藏测试、旧运行轨迹或其他臂产物。参考答案和测试只在宿主评分侧使用。经验来源和内容保存在独立的library.json中用于审计；模型仅获得该题选中的文本。

Requests 的历史超时测试要求 `10.255.255.1:80` 不接受连接。Windows Docker 的网关可能实际转发该地址；评分前会在独立评分容器网络命名空间内设置该地址的 `/32` 链路路由，并验证真实TCP连接超时。只有评分容器具备配置该路由所需的 `NET_ADMIN`；不修改宿主路由、测试断言或模型容器权限。准备失败记为评分基础设施错误。两组评分使用相同设置。

## 运行

```powershell
npm run benchmark:swe-holdout -- catalog
npm run benchmark:swe-holdout -- prepare
npm run benchmark:swe-holdout -- run
npm run benchmark:swe-holdout -- status
```

`catalog`只冻结经验和任务清单，不调用模型。`prepare` 首次生成索引和适用性选择，再下载并固定镜像，检查每题原代码红、参考补丁绿；它会调用检索文本模型，但不执行修复任务。`run` 自动完成缺失准备后运行80次修复任务。39条候选和40题最多增加39次索引请求及40次适用性请求，无召回则不请求判断。索引失败和中断均记录，未知付费中断不自动重试。任务阶段预算继承Mini的15分钟，单次命令最多120秒；评分另有超时。参考补丁未通过时停止，不自动替换题目。

默认数据根 `.picoding/benchmarks/swe-holdout-v2`，来源 `.picoding/benchmarks/swe-mini-r0-b-v1`；可在操作名后依次指定这两个目录。使用独立批次锁，已有完整结果恢复时跳过；未知的付费中断不自动重跑。评分设施失败后保存补丁，恢复仅重新评分。强制终止留下锁时，必须先确认锁内PID已经退出再处理；不要删除证据或修改指纹来绕过配置漂移。

## 结果

- `tasks.md`、`catalog.json`：固定任务清单。
- `library.json`、`source-catalog.json`、`retrieval.json`：冻结经验、来源任务、逐题检索。
- `retrieval-v2.json`、`retrieval-index/`：V2 冻结索引、逐题召回、选择理由、引句、错误和模型用量。
- `protocol.json`：源码、私有评分材料、模型、镜像和检索哈希。
- `batch.json`：逐臂检查点与当前任务。
- `agent-data/runs/`：逐次trace、补丁、usage和官方评分记录。
- `summary.json`、`report.md`：总体与两类泛化分组统计、完整配对token、共同成功token、总耗时和逐题胜负。

成功率使用固定分母40（分组各20），未完成时属于暂定结果。缺失usage不填零，不将失败提前退出当作提效。token包含缓存读取；SDK费用是估计值。V2 索引与筛选用量单独记录在检索产物中，不包含在配对修复 token 表，比较总成本时应另行加总。经验文本输入开销已计入经验组；历史Mini经验构建开销不重复计入本轮推理增量成本，也不能称为免费。

本实验检验“未用于经验提炼的新任务”上的迁移，不证明模型预训练没有见过公开题目。每题每组一次，样本量小；应同时看改善/退化与两类泛化，不能仅凭总体百分点或少数案例宣称稳定收益。
